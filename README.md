# جَرّتي — توصيل أسطوانات الغاز في المفرق

تطبيق ومموقع لتبديل وتوصيل أسطوانات الغاز في مدينة المفرق — الأردن.
أسطوانة حديد أو بلاستيك بـ **7.00 د.أ**، وأجرة توصيل **0.10 د.أ** لكل طلب، والدفع **نقداً عند التسليم**.

```
7.00 + 0.10 = 7.10 د.أ   (أسطوانة واحدة)
14.00 + 0.10 = 14.10 د.أ (أسطوانتان)
```

## ما يحتويه المستودع

| المسار | الوصف |
| --- | --- |
| `index.html` | صفحة الهبوط (الصفحة الرئيسية) — عربية RTL بخط Cairo |
| `landing.css` | تنسيقات صفحة الهبوط |
| `screens.html` + `styles.css` | معاينة شاشات التطبيق الأربع (HTML/CSS) |
| `img/` | صور التوصيل والمستودع وحي المفرق |
| `app/` | تطبيق Flutter لأندرويد وiOS |

## المرحلة الأولى — ما تم إنجازه

- صفحة هبوط جديدة كاملة: الأسعار، الخطوات، المزايا، المناطق، الأسئلة الشائعة، والتنزيل.
- هيكل مشروع Flutter نظيف: `lib/app`, `lib/core`, `lib/data`, `lib/features`, `lib/shared`, `lib/state`.
- شاشات تعمل فعلياً:
  - **تسجيل الدخول** برقم هاتف أردني + اختيار الدور (عميل / موزّع).
  - **رمز التحقق OTP** مع عدّاد إعادة الإرسال.
  - **الرئيسية والطلب**: نوع الأسطوانة، الكمية، العنوان، ملاحظة، ملخص الفاتورة.
  - **تتبّع الطلب**: الحالات الأربع، خط زمني، خريطة توضيحية، بيانات الموزّع.
  - **طلباتي**: سجل الطلبات مع إعادة الطلب بضغطة.
  - **حسابي**: الاسم، الهاتف، العناوين المحفوظة، طريقة الدفع، تسجيل الخروج.
- تخزين محلي للجلسة والطلبات والعناوين (`shared_preferences`) ليعمل التطبيق بلا خادم.
- خط Cairo محلي داخل `app/assets/fonts` (وزنان: 400 و 700) — لا اتصال بالإنترنت لتحميل الخط.
- أسعار التطبيق تُقرأ عبر `PricingRepository` وليست مثبّتة في الواجهة؛ القيمة الحالية احتياطية حتى ربط الخادم.
- اختبارات وحدة للأسعار وأرقام الهواتف: `flutter test`.

## تشغيل الموقع

افتح `index.html` مباشرة في المتصفح، أو شغّل سيرفراً محلياً:

```bash
python3 -m http.server 3000
```

ثم افتح `http://localhost:3000/` (صفحة الهبوط) و`http://localhost:3000/screens.html` (الشاشات).

## تشغيل التطبيق

المتطلبات: Flutter **3.50** أو أحدث (Dart 3.14+) وAndroid Studio لأندرويد أو Xcode لـ iOS.

```bash
cd app
flutter pub get
flutter run
```

### رمز التحقق في النسخة التجريبية

النسخة الحالية بلا خادم، لذا رمز التحقق الثابت هو:

```
123456
```

أي رقم أردني صحيح يبدأ بـ 077 / 078 / 079 يُقبل. هذا مؤقت ويُستبدل بمزوّد OTP حقيقي في المرحلة الثالثة.

### بناء APK

```bash
cd app
flutter build apk --release
# الناتج: build/app/outputs/flutter-apk/app-release.apk
```

أو افتح مجلد `app/android` في Android Studio. التوقيع حالياً بمفتاح debug؛ قبل النشر على Google Play أنشئ keystore خاصاً في `android/key.properties` (مستثنى من git).

### iOS

```bash
cd app
flutter pub get
cd ios && pod install && cd ..
open ios/Runner.xcworkspace
```

اختر الفريق (Signing Team) في Xcode ثم Run. مشروع `ios/` جاهز للبناء من Xcode.

### الأيقونة وشاشة البداية

أيقونة التطبيق هي هوية جَرّتي: مربّع كهرماني متدرّج يحمل أسطوانة غاز كريمية بمقبض كحلي. وُلدت من الكود لا من ملف تصميم، لذا يمكن إعادة توليدها أو تعديلها بأمر واحد:

```bash
cd app
python3 tool/generate_brand_icons.py   # يتطلب Pillow
```

يُحدَّث تلقائياً:

- أندرويد: `ic_launcher` و`ic_launcher_round` لكل كثافة، و`ic_launcher_foreground` للأيقونة التكيّفية (Android 8+)، وشعار شاشة البداية `launch_logo`.
- iOS: كل مقاسات `AppIcon.appiconset` (1024 بلا شفافية كما تشترط Apple) وصور `LaunchImage`.

شاشة البداية الأصلية (native splash) تظهر بخلفية كريمية `#FCFAF7` مع شعار الأسطوانة في المنتصف: عبر `launch_background.xml` حتى أندرويد 11، و`windowSplashScreen*` في `values-v31` لأندرويد 12+، و`LaunchScreen.storyboard` على iOS. الألوان معرّفة في `android/app/src/main/res/values/colors.xml`.

## لماذا Supabase؟

اخترت **Supabase** بدل Firebase لأن:

1. قاعدة بيانات **PostgreSQL** حقيقية: جداول الطلبات والمناطق والموزّعين والعلاقات بينها أوضح، وتقارير صاحب الديانة (مبالغ محصّلة، طلبات اليوم) تُكتب بـ SQL مباشرة.
2. **Realtime** جاهز: تحديث حالة الطلب وقبول الموزّع يصل للعميل فوراً دون إدارة بنية إضافية.
3. سياسات **RLS** تسمح بضبط الصلاحيات بدقة: العميل يرى طلباته فقط، والموزّع يرى طلبات منطقته، والإدارة ترى الكل.
4. تسعير أوضح وتكلفة OTP والمكالمات قابلة للفصل عن قاعدة البيانات.

البديل Firebase مناسب أيضاً، لكن نموذج المستندات يجعل تقارير المبالغ والمناطق أقل مباشرة.

### ربط الخادم (المرحلة الثالثة)

لا تضع أي مفتاح داخل الكود. مرّر القيم وقت البناء:

```bash
flutter run \
  --dart-define=SUPABASE_URL=https://YOUR-PROJECT.supabase.co \
  --dart-define=SUPABASE_ANON_KEY=YOUR_PUBLIC_ANON_KEY
```

والتطبيق يهيّئ Supabase تلقائياً عند وجود القيمتين (`lib/core/config/app_config.dart`).
المفتاح المستخدم هو **anon/publishable** فقط — لا يُستخدم مفتاح service_role في التطبيق أبداً.

نقاط الربط المعرّفة حالياً:

- `AuthRepository` — يستبدل الرمز التجريبي بـ `signInWithOtp` / `verifyOTP`.
- `PricingRepository` — يقرأ الأسعار من جدول `pricing` (قراءة عامة فقط).
- `OrderRepository` — يستبدل التخزين المحلي بجدولي `orders` و`order_events`.

## المراحل القادمة

1. **المرحلة الثانية — واجهة الموزّع:** الطلبات المتاحة، قبول/رفض، تأكيد التسليم، الأرباح اليومية.
2. **المرحلة الثالثة — الخادم:** Supabase (جداول + RLS + OTP حقيقي + Realtime) وربط الإشعارات.
3. **المرحلة الرابعة — لوحة صاحب الديانة:** طلبات اليوم، المبالغ المحصّلة، إدارة الموزّعين والمناطق (المفرق، الفدين، الجديدة، بلعما، المنشية).
4. **المرحلة الخامسة — الإطلاق:** خريطة حقيقية، أيقونة التطبيق، التوقيع، متجر Google Play وApp Store.

## ملاحظات صريحة

- الطلبات في هذه المرحلة تُحفظ على الجهاز فقط؛ لا يراها موزّع حقيقي بعد.
- شاشة التتبّع تحاكي تغيّر الحالة بزر «محاكاة تحديث الحالة» إلى حين ربط Realtime.
- الخريطة رسم توضيحي (CustomPainter) وليست خريطة GPS حقيقية.
- بيانات الموزّع في شاشة التتبّع تجريبية، وأزرار الاتصال/واتساب تعرض تنبيهاً فقط.
- أيقونات التطبيق ما زالت الافتراضية من Flutter وتُستبدل بهوية جَرّتي قبل النشر.
